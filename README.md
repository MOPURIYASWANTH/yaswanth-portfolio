## Prerequisites
- Node.js 20+ and npm
- Java 21
- Maven 3.9+ (or use the Maven wrapper generated by your IDE)
- MySQL 8+

## 1. Start MySQL
Create a database:
```sql
CREATE DATABASE yaswanth_portfolio CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Create a local MySQL user or use your existing development account. Do not use a production database password in source control.

## 2. Start backend
```bash
cd backend
```
Set environment variables (PowerShell example):
```powershell
$env:DB_URL="jdbc:mysql://localhost:3306/yaswanth_portfolio"
$env:DB_USERNAME="root"
$env:DB_PASSWORD="your-local-password"
$env:CORS_ALLOWED_ORIGINS="http://localhost:5173"
mvn spring-boot:run
```
Backend defaults to `http://localhost:8080`. JPA creates the contact table in local `update` mode. For production, use a migration tool such as Flyway and set `DB_DDL_AUTO=validate`.

Health check:
`GET http://localhost:8080/api/health`

Contact endpoint:
`POST http://localhost:8080/api/contact`
```json
{
  "name": "Recruiter",
  "email": "recruiter@example.com",
  "subject": "Java Developer opportunity",
  "message": "I'd like to discuss an opportunity."
}
```

## 3. Start frontend
```bash
cd frontend
npm install
```
Create `.env` from `.env.example` and set:
```env
VITE_API_BASE_URL=http://localhost:8080
```
Then:
```bash
npm run dev
```
Open the local Vite URL shown in the terminal.

## 4. Customize before publishing
1. Edit `frontend/src/data/portfolio.js`.
2. Replace `#` project links with verified GitHub/live-demo URLs or leave them as unavailable.
3. Add your actual resume PDF to `frontend/public/resume.pdf`.
4. Confirm your email, LinkedIn, and GitHub URLs.
5. Test the contact form against your deployed API.
6. Do not publish secrets or commit `.env` files.

## 5. Production deployment outline
- Frontend: deploy `frontend` to Vercel. Set the project root to `frontend`, build command `npm run build`, output directory `dist`, and environment variable `VITE_API_BASE_URL` to the public backend URL.
- Backend: deploy `backend` to a Java-capable host such as Render. Build command `mvn clean package`; start command `java -jar target/portfolio-api-1.0.0.jar`. Set `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `CORS_ALLOWED_ORIGINS`, and `DB_DDL_AUTO=validate`.
- Database: use a managed MySQL-compatible service whose current free-tier terms and availability you have verified. Configure its connection URL, TLS requirements, allowed networks, and credentials as required by the provider.
- Add the exact frontend origin to `CORS_ALLOWED_ORIGINS`; do not use `*` in production.
- Free plans can sleep, have resource limits, or change terms. Check provider documentation before choosing a provider.

## API
- `GET /api/health` — basic health response
- `POST /api/contact` — validates and stores a message
- `GET /api/projects` — returns portfolio project data

## Accessibility and performance
- Semantic landmarks, visible focus states, form labels, status announcements, reduced-motion handling.
- 3D is lazy-loaded and has a CSS fallback.
- Keep images compressed and avoid unnecessary libraries or autoplay audio/video.
- Run `npm run build`, inspect browser console/network, and test keyboard-only navigation and a mobile viewport before release.

## Security checklist
- Keep database credentials in environment variables.
- Use HTTPS in production.
- Add rate limiting / CAPTCHA or a trusted form provider before exposing the contact endpoint publicly.
- Add request-size limits and logging/monitoring before production use.
- Configure allowed origins explicitly.
- For a serious production deployment, use Flyway migrations and database backups.
